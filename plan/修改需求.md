# 好好走：地圖標點與搜尋框修改需求

- 分支：`navigation`（第 1～4 點看的是 `9775f5e`，第 5 點看的是 `75670be`）
- 寫於 2026-11-08，以臺北車站周邊、縮放 17 的畫面為準

這份文件只描述要改什麼，程式還沒動。

---

## 1. 地圖縮小時要減少標點

### 現在的狀況
- 標點只分兩段（`src/marker-layout.mjs` 的 `selectMapMarkers`）：
  - 縮放 **小於 16**：只顯示捷運站和地標。
  - 縮放 **16 以上**：所有設施一次全部出現，包括廁所、飲水處、座椅、停車場、公車站、醫療、公園、捷運出口。
- 所以縮放 16、17 時畫面上全是圖標，看不到路。
- 重疊的圖標只會合併成一個帶「+」的點（`groupMarkers`），數量不會變少。

### 要改成
依縮放分層顯示，越縮小顯示越少：

| 縮放 | 要顯示的 |
|---|---|
| 15 以下 | 捷運站、重要地標 |
| 16 | 再加上捷運無障礙出口／電梯、無障礙廁所 |
| 17 | 再加上一般公廁、停車場（有身障車位）、公園、醫療 |
| 18 以上 | 全部，包括飲水處、座椅、公車站、友善店家 |

- 使用者在「找設施」選了某個類別時，那個類別不受上表限制，照樣顯示。
- 同一層裡如果還是太密，依距離畫面中心排序，**每一格只留一個**，不要用「+」堆在一起。
- 起點、終點、最近選過的地點永遠顯示。

### 驗收
- 縮放 16，臺北車站一帶畫面上的圖標數要明顯少於現在。用 `document.querySelectorAll('.fac-pin').length` 比較，目標是少一半以上。
- 每放大一級，新出現的類別要符合上表。

## 2. 標點旁邊要有文字

### 現在的狀況
- 只有地標、友善店家、一般店家會顯示名稱（`MapView.jsx` 的 `hasLabel`）。
- 廁所、停車場、捷運出口、公園等都只有圖標，要把滑鼠移上去或點開才知道是什麼。

### 要改成
- **每個單獨顯示的標點旁邊都要有名稱**，跟 Google 地圖一樣顯示在圖標下方或右邊。
- 文字和其他圖標或文字重疊時，**優先拿掉圖標**（照第 1 點減少標點），不要只顯示圖標而不顯示字。
- 名稱太長就截斷加「…」，最多約 8 個中文字。
- 名稱只有類別（例如「飲水處」「座椅」）的，改顯示「類別＋所在地」，例如「飲水處・二二八公園」。做不到的就不顯示文字，只留圖標，但這類圖標要排在最後才顯示（見第 1 點）。
- 這一點要等第 3 點的資料清洗做完才會好看，不然會顯示出代碼、`<br />` 和車位數。

## 3. 資料清洗（就是現在圖標旁邊有「+」的那些）

### 「+」是什麼
地圖上帶「+」的圖標，代表那個位置有好幾筆資料疊在一起，點下去會跳出「選擇設施」清單。很多「+」其實是**同一個地方重複登記**，不是真的有好幾個設施。

### 重複資料
只算地圖會顯示的類別（不含坡道、一般店家、道路），**同類別、相距 10 公尺內的有 1,337 對**：
- 同一地點座標完全一樣的有 455 對。
- 名稱相同的有 621 對。
- 來自不同資料來源的有 443 對。

最常見的例子：
- **停車場重複兩份來源**：`wheel-15`（停車場清單）和 `wheel-16`（身障車位）列的是同一個停車場，例如「玉泉公園停車場」和「TPE0426-大同區-玉泉公園停車場(…)」相距 9.9 公尺。
- **同一個停車場登記好幾次**：「建國高架橋下停車場」在幾公尺內就出現 4 次，「台北地下街停車場」2 次。
- **公車站同名兩筆**：「臺北車站」和「臺北車站)」在同一點，「捷運小南門站」也一樣。
- **同一棟樓的不同店家**，例如臺北地下街的友善店家疊在同一個座標。這種是真的不同店，**不要合併**，但要讓清單看得出差別。

**合併規則（建議）：**
- 同類別、相距 15 公尺內、名稱清洗後相同或其中一個包含另一個 → 合併成一筆，保留資訊較完整的那筆（例如有車位數的）。
- `wheel-15` 和 `wheel-16` 的停車場 → 用名稱比對後合併，車位數放進詳細資料。
- 不同類別的（例如停車場和它的電梯）不要合併。

### 名稱髒資料
以下都是地圖會顯示的類別，全臺北的筆數：

| 問題 | 筆數 | 例子 | 怎麼清 |
|---|---|---|---|
| 名稱前有代碼 | 1,823 | `B02050001-幸安學坊`、`TPE1648-大同區-…` | 拿掉 `B0…-`、`TPE…-`、`○○區-` 前綴 |
| 名稱裡塞了車位數 | 1,709 | `…停車場(大型車:0格，小型車:42格(含身心障礙停車位2格)…` | 括號內的車位數移到詳細資料欄位，名稱只留停車場名 |
| 結尾多一個 `)` | 665 | `松山商職)`、`臺北車站)` | 刪掉沒有配對的右括號 |
| 店名和地址黏在一起 | 378 | `Cozzi Cafe 敦南店-臺北市大安區敦化南路二段218號…` | 用「-臺北市／-台北市」切開，前面是名稱，後面放地址 |
| 停車場名稱被截在 10 個字 | 285 | `臺北市萬華運動中心停`、`維多利亞酒店附設停車` | 用 `wheel-16` 或其他來源的完整名稱補回；補不到就補「…場」 |
| 含 `<br />` HTML | 148 | `幸安學坊<br />臺北市中正區…<br />27555690#211` | 用 `<br />` 切開：名稱、地址、電話分三個欄位 |
| 含換行或引號 | 15 | `"阿立圓山玩具模型社 ⏎MJ Model Railroad"` | 去掉引號，換行改空白 |
| 亂碼 `?` | 32 | `?公圳公園`（瑠公圳）、`新糖?公園` | 對照原始資料修正，修不了的列出來人工處理 |
| 名稱只有類別 | 2,600 | OSM 的「飲水處」「座椅」 | 見第 2 點，補上所在地名稱 |

### 在哪裡清
- 在資料處理流程裡清（`npm run data:sync` → `scripts/sync_data.py`，`npm run data:pack` → `scripts/pack_data.py`），產生乾淨的 `public/data/*.json.gz`。
- **不要在前端顯示時才清**，不然搜尋、詳細卡、地圖會各自不一致。
- 每一條清洗規則都要有測試，用上表的例子當測試資料。

### 驗收
- 清洗後重新跑一次統計，表中每一項都應該接近 0（亂碼人工處理的除外）。
- 臺北車站一帶的「+」圖標明顯變少，剩下的點開來每一筆都是不同的地方。

## 4. 搜尋框與規劃選項

### 4-1「找設施」分頁的搜尋框刪掉
- 現在「找設施」分頁最上面有一個「搜尋地點、捷運站或路名」，刪掉。
- 這個分頁只留類別按鈕（無障礙廁所、飲水台、椅子…）和「離地圖中心由近到遠」的清單。

### 4-2「規劃路線」一開始只有一個搜尋框
- **一開始**：「規劃路線」分頁只顯示一個搜尋框（例如「想去哪裡？」），不顯示出發地、目的地兩列，也不顯示「定位」和「更多規劃選項」。
- **按下搜尋框、選好目的地之後**：才出現現在這一整套，包括「從哪裡出發／想去哪裡」兩列、交換按鈕、「定位」、「規劃路線」按鈕。「更多規劃選項」不會出現，見 4-3。
- 出發地預設維持現在的「我的位置」。
- 清除目的地，或回到這個分頁的初始狀態時，要回到只有一個搜尋框的樣子。

### 4-3「更多規劃選項」整個刪除，固定用輪椅
- 現在「規劃路線」裡有一個可以展開的「更多規劃選項」（`App.jsx` 的 `<details className="settings-advanced plan-extras">`），裡面有：
  - 出行身分按鈕：輪椅、嬰兒推車、樂齡（`src/trip-extras.mjs` 的 `IDENTITIES`）
  - 示範路線按鈕（`DEMOS`，例如大安森林公園）
  - 通行偏好列：「避開階梯與施工」和調整偏好的按鈕
- **整個區塊刪掉**，畫面上不再出現「更多規劃選項」。
- 路線規劃**直接固定用輪椅的條件**：`identity: "wheelchair"`，最小寬度 0.9 公尺、最大坡度 5%、走法 `gentle`。
- 已經存過其他身分（嬰兒推車、樂齡）的使用者，打開後也要改回輪椅。
- 刪掉後沒有地方再用到的程式（`IDENTITIES`、`DEMOS`、`runDemo` 等）一起清掉，相關測試跟著調整。
- 待確認：第一次打開時跳出的「設定主要出行方式」視窗（一般步行、輪椅…）要不要也拿掉、直接當成輪椅？

### 4-4 定位成功後不要有提示
- 定位**成功**時，目前會出現兩種提示，都拿掉：
  - 跳出的提示「已找到你的位置，可以看看附近有哪些設施。」（`App.jsx` 的 `locate()`）
  - 出發地「我的位置」下面的小字「定位誤差約 X 公尺」或「定位精度未知」（`point.needsConfirmation` 那一行）
- 定位成功就只是把出發地設成「我的位置」、地圖移過去，不顯示任何文字。
- 定位**失敗**的提示保留，例如權限沒開、逾時、在臺北範圍外，不然使用者不知道為什麼沒反應。

### 4-5「朗讀搜尋結果」按鈕刪除
- 搜尋視窗（「從哪裡出發？／想去哪裡？」）裡，搜尋框下方的「朗讀搜尋結果」按鈕刪掉（`App.jsx` 搜尋視窗的 `search-options` 裡第一個按鈕，呼叫 `speakText(...)` 那個）。
- 同一排的「在地圖上點選」保留。
- 只刪搜尋結果的朗讀。路線頁的「聽路線」和設定裡的「朗讀速度」這次不動。

### 驗收
- 打開搜尋視窗，找不到「朗讀搜尋結果」。
- 按「定位」成功後，畫面上沒有跳出提示，出發地下面也沒有誤差小字。
- 打開「規劃路線」，找不到「更多規劃選項」。
- 規劃路線時送出的條件是輪椅（寬度 0.9 公尺、坡度 5%）。
- 打開「找設施」，畫面上找不到搜尋輸入框。
- 打開「規劃路線」，只看到一個搜尋框；選了目的地後，才看到出發地、目的地兩列和「規劃路線」按鈕。
- 手機和電腦都要確認。

## 5. 開了「隱藏地圖圖標」後，在地圖上點選會出問題

檢查於 `navigation` `75670be`，在電腦版瀏覽器實測（假定位在臺北車站）。

### 實測結果
1. 開「隱藏地圖圖標」→「想去哪裡」→「在地圖上點選」→ 點地圖：**目的地有設成功**（「地圖上選的位置」），console 沒有錯誤。
2. 接著按「規劃路線」：結果是「尚未找到連接兩地的路線」。
3. 關掉「隱藏地圖圖標」，用**同一個座標**（25.04631, 121.52002）再規劃一次：**一樣失敗**。所以「找不到路線」本身不是隱藏圖標造成的，而是地圖上隨便點的座標常常不在人行路網上。
4. 隱藏圖標會讓這個情況嚴重很多，原因在下面。

### 找到的問題
**(1) 隱藏圖標時，人行道圖層也一起被關掉（主因）**
- `MapView.jsx`：`useSidewalkLayer(map, location, showOfficialSidewalk && !hideMapIcons, …)`。
- 結果是使用者看不到哪裡有人行道，也沒有設施圖標可以點，只能在空白地圖上盲點。點到馬路中間或建築物裡，就連不上路網。
- 圖標開著的時候，使用者通常會點到設施或捷運出口，那些點本來就在路網旁邊，所以比較容易成功。
- **要改**：隱藏圖標只隱藏設施圖標，**人行道線要照「人行道」開關顯示**，不要跟著隱藏。

**(2) 隱藏圖標時底圖只剩道路線**
- `MapView.jsx` 的底圖設定：隱藏圖標時把 `close.minZoom` 改成 11，導致：
  - 原本的 OpenStreetMap 底圖不加（`close.minZoom > 11` 不成立）
  - 「無文字電子地圖」（`EMAPX99`）也不加（`if (!hideMapIcons)`）
  - 只剩「道路路網」疊加層
- 地圖上看不到建築、公園、車站範圍，更難判斷要點哪裡。
- 而且那一層沒有接上載入狀態回報（沒有經過 `watch()`），底圖狀態會一直停在「loading」，圖磚載入失敗也不會提示。
- **要改**：隱藏圖標時應該改用「無文字電子地圖 + 道路路網」，不是只有路網；並且要用 `watch()` 接上載入狀態。

**(3) 點完之後「請在地圖上點選目的地。」的提示還留在畫面上**
- 選點完成後，上方提示沒有自動消失，看起來像還沒選好。
- **要改**：選點成功（`changePoint`）或取消選點時，清掉這個提示。

**(4) 地圖點的位置不在路網上時，要自動貼到最近的人行道**
- 現在是直接用點的座標規劃，常常連不上。
- **要改**：選點時先貼到最近的人行道或路口（例如 30 公尺內），貼不到再提示「這裡附近沒有可通行的人行道，請點靠近人行道的位置」。這一點不管有沒有隱藏圖標都需要。

**(5) 隱藏圖標時，路線上的施工也不顯示**
- `App.jsx`：`constructionConflict={tab && !hideMapIcons ? constructionConflict : null}`，官方不利通行點也是 `!hideMapIcons` 才畫。
- 施工和不利通行是路線安全資訊，不是一般圖標，**規劃出路線後不應該被「隱藏地圖圖標」藏起來**。

### 驗收
- 開「隱藏地圖圖標」後：設施圖標不見，但人行道線和底圖（無文字電子地圖）都還在。
- 在地圖上點人行道附近的位置當目的地，可以規劃出路線。
- 點完後「請在地圖上點選…」的提示會消失。
- 規劃出的路線若經過施工，隱藏圖標時仍然看得到施工標示。

## 建議順序
1. 先做第 3 點資料清洗，因為第 2 點顯示文字要靠乾淨的名稱。
2. 再做第 1 點分層減少標點、第 2 點顯示文字，兩個一起調畫面。
3. 第 4 點搜尋框和規劃選項跟前面不相關，可以獨立先做。
4. 第 5 點的 (1)(3)(5) 改動小，可以跟第 4 點一起做；(2)(4) 要另外測試底圖和路網。

每一步都要跑 `npm test` 和 `npm run build`，再用瀏覽器在縮放 15、16、17、18 各截一張圖比較。
