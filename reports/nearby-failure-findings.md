# 附近人行路網候選：失敗樣本重測

2026-11-07 22:18（臺北時間），對 `reports/mixed-place-after-floor.json` 中 19 組失敗樣本，使用目前本地路網、地點資料與 22:10:51 更新的施工快照重新測試。逐組先計算原地點路線，再從乾淨路網建立獨立 worker，模擬使用者手動搜尋附近位置；每組整個測試包含原路線與候選查詢，以 45 秒為限。沒有測官方線上路由、即時電梯維修或現場情況；樣本不是全市成功率。

六組候選分別為南京三民→臺北光復郵局（目的地 3 點，距原地點直線 15／24／33m）、星辰大飯店→善導寺（起點 3 點，16／28／45m）、忠孝新生→晨曦生活診所（目的地 3 點，18／22／37m）、古亭→座椅（目的地 1 點，64m）、開丼→大安森林公園（起點 3 點，16／24／39m）、古亭→湧聲公園（目的地 1 點，73m）。這些是可與另一端規劃的人行路網點，不一定是建物入口；到原地點剩餘路程和樓層未確認，均未自動選擇，也未計為原地點路線成功。

候選搜尋有 80m 半徑、每側最多 12 次嘗試與每側時間限制；18／19 組曾達到部分搜尋上限。13 組未提供候選僅表示這次有限搜尋沒有找到，不能推論附近沒有其他可達位置。每組測試耗時中位數 12.2 秒、最長 32.8 秒，包含原路線重算及兩次路網載入，並非使用者介面單純候選搜尋的延遲。

重現方式：先啟動本機應用並確認施工 API 有新鮮資料，執行 `node scripts/benchmark-nearby-failures.mjs`。完整逐組資料、候選、截斷狀態、路網與 POI 檔 SHA-256 和施工更新時間保存在 `reports/nearby-failure-benchmark.json`。施工資料會變動；每次重測時不能假定輸出數字一致。
