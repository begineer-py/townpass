# 路線逾時與無路結果混淆

- 功能：路線計算超時時，畫面應說明搜尋未完成，不應讓使用者以為已確認無路。
- 原因：本機 A* 主搜尋原本沒有訪問節點或時間上限；超出 API 時限後回傳 HTTP 504，但前端把非 503 busy 的錯誤統一分類為路線服務連線失敗。若主搜尋先回 `NO_ROUTE`，後續備援查詢失敗也可能被「找不到路線」蓋過。
- 修復：主搜尋增加 8 秒／100,000 節點上限，分別回報 `ROUTE_SEARCH_TIMEOUT` 或 `ROUTE_SEARCH_LIMIT`；API 504 傳遞成 `ROUTE_BACKEND_TIMEOUT`；無路提示說明只代表目前圖資與條件未找到連通路徑，並顯示備援搜尋錯誤。
- 限制：圖資仍可能缺漏或不連通。逾時／運算上限表示搜尋未完成，不等同確認有路或無路；未以使用者提供的起終點重現原始現象。
