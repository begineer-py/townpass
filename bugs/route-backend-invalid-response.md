# 路線規劃異常回覆造成卡住

- 功能：規劃路線應在後端出錯、回覆格式異常或逾時時結束等待，讓使用者重試。
- 重現：模擬 HTTP 200 回傳錯誤的類型或請求 ID；舊前端忽略回覆，第一個請求不結束、後續請求卡在佇列。這是異常回覆測試，並非正常後端回覆必然錯誤。
- 相關程式：`src/backend-route-worker.mjs` 未驗證回覆，`src/route-worker-lifecycle.mjs` 忽略不符的事件。
- 修復：驗證回覆類型、ID 和內容；異常立即回報錯誤。前端請求設 55 秒上限並中止，之後可重新規劃。
- 驗證：自動測試涵蓋錯誤類型、ID、空內容、逾時、中止及重新規劃。
