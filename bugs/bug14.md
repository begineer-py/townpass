# BUG-14：地址搜尋尚未完成就顯示找不到

- 類別：搜尋／非同步狀態
- 重現版本：`1b5b868`
- 狀態：已修正，桌面瀏覽器重測通過

## 重現

搜尋「臺北市信義區永吉路30巷92號」或「臺北市內湖區金湖路363巷51弄23號」。桌面瀏覽器在地址候選出現前短暫顯示「還沒找到這個名稱」，之後才顯示完全相同的地址。這可能讓使用者在搜尋仍在進行時誤以為沒有結果。

## 資料與原因

兩個地址由 `reports/address-map-benchmark.json` 使用 seed 110 和 LCG 抽得 index 5、0；畫面候選文字與地址一致，UI 未顯示座標，尚未確認與樣本座標完全相同。`src/App.jsx` 在查詢變更時先清空地址結果，延遲 350ms 才呼叫非同步地址與地標搜尋，但空狀態只看目前結果數：

```jsx
{query && !searchResults.length && <div>還沒找到這個名稱…</div>}
```

## 修復

顯示查詢中狀態，等本輪地址與地標搜尋完成後才顯示無結果；切換查詢時不再混入先前查詢的遠端結果。搜尋結果朗讀在查詢期間也改為說明仍在搜尋。此修復不改地址資料或路由。

## 驗證

桌面瀏覽器重新搜尋上述兩個地址，先顯示「正在搜尋地點」，再顯示對應候選；不存在字串在搜尋結束後才顯示無結果。快速切換兩個地址後只見後者結果。`npm test` 240／240 與 `npm run build` 通過。本次未模擬搜尋 API 故障或實際斷網。
