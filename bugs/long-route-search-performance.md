# 長路線候選搜尋過久及提早達上限

- 功能：以自有後端規劃並比較人行道路線；候選仍須通過獨立驗證，不能將搜尋上限當作沒有路線。
- 資料：以台北小巨蛋至景美、即時施工資料測試。調整前本機冷啟動主路線約 9.1 秒、候選約 4.0 秒且回傳 `PROVISIONAL_SEARCH_LIMIT`；調整後主路線約 7.0 秒、候選約 2.4 秒，找到 1 條通過獨立驗證的候選。候選搜尋狀態為 `incomplete`，不代表已搜尋所有可能路線。時間為單次本機測試，非正式環境保證。
- 原因：區域選取重複掃描完整路網；端點搜尋反覆掃描全部節點；候選網路粗格將遠距離點計入配對上限，Dijkstra 則在長線達到訪問上限。搜尋也反覆配置費用明細物件及重建端點驗證器。
- 修復：重用原路網空間格網並保留未索引邊及完整掃描備援；端點搜尋使用格網並保留最近距離與投影節點；採用較細的候選接合格網（容量不足時退回原格網）及保守 A* 下界；沿用原 2 公尺接合、施工、道路與獨立驗證規則。
- 驗證：完整真實路網多組範圍之索引結果與全掃描一致；100 組混合模擬路線的細格 A* 與粗格 Dijkstra 費用一致；長路線原主路線幾何及費用一致，候選經 `official-source-screened-v1` 獨立驗證。
