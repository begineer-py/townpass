# BUG-04：官方路線驗證失敗時未嘗試本機路網

- 類別：功能／路線規劃
- 重現版本：`6112846`；修復狀態：備援流程已修正，示範路線仍失敗
- 環境：本機 Vite `127.0.0.1:5188`，一般步行；2026-11-07

## 功能與重現

開啟「規劃路線」，等待路網載入後選「大安森林公園」示範。起點為 `(25.0332, 121.5355)`，終點為 `(25.0301, 121.5356)`。第四輪固定版本回報「這個地點可能有不同入口」，沒有路線；此文案對應 `OFFICIAL_ENTRY_UNVERIFIED`。原預期是官方候選未通過驗證時，仍可嘗試使用原選點與現行限制，從本機路網尋找另一條通過檢查的路線。

## 資料與原因

示範座標固定在 `src/trip-extras.mjs` 的 `DEMOS`。官方路由有回應但驗證不過時，`src/App.jsx` 原本直接顯示錯誤；只有官方服務本身回傳錯誤才呼叫 `startLocalFallback`。網頁使用即時施工資料，因此結果可能隨資料及服務狀態改變。另一個瀏覽器初測也發現信義與北投示範失敗，但當時服務版本正在修改中，尚不能視為此固定版本的重現。

## 相關程式與修復

修正前驗證分支只執行：

```js
if (verified.error || invalidProof) setRouteError(verified.error || 'UNVERIFIED_NETWORK');
```

修正後，入口、路徑、過街、道路衝突及施工封閉等候選驗證失敗，會嘗試 `startLocalFallback`。備援繼續使用原選點、偏好和新鮮施工資料，並由本機路網獨立驗證；施工資料不可用或路網證明無效不會因此被略過。

## 修復後驗證與未解問題

`npm test` 162 項通過，`npm run build` 通過。瀏覽器重跑同一示範，文案變成 `NO_CONNECTION` 對應的「選擇實際使用的人行入口」，可確認備援有回應，但仍沒有路線。**示範尚未修好**：需進一步確認兩個固定選點與已驗證人行路網之間的實際入口與圖資，補充可信資料後重測；不可直接虛構可通行連線。

在 `59a355c` 的獨立本機服務、桌面瀏覽器及一般步行設定下，三條內建示範皆產生路線：大安森林公園 835 公尺、信義 591 公尺、北投約 1.2 公里。示範已改用資料集中的出入口，與原先手寫座標不同；因此這不能證明原座標本身已可通行。信義與北投顯示入口估算及現場確認提醒。施工資料更新時間約 22:00:41，結果可能隨即時資料改變。
