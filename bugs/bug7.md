# BUG-07：相同施工工程通報佔滿沿途施工清單

- 類別：資料／介面
- 重現版本：`38f53bd`
- 狀態：已修正顯示並完成瀏覽器重測

## 功能與重現

以南京三民站出發，選擇臺北光復郵局附近的可達人行路網候選並規劃路線。沿途施工資料顯示相同的「寧安公園(南京東路4段120巷側)人行道更新工程」六次，使其他施工資料可能無法進入六筆顯示上限。

## 資料與原因

2026-11-07 即時施工 API 中，該工程的 `11501492-1` 至 `11501492-10` 有相同地址、日期、通行影響與 14 個幾何形狀；十筆幾何資料的 SHA-256 前 12 碼均為 `9a2a84270d9d`。來源通報有多筆編號，不能直接視為可以刪除的資料。

`src/App.jsx` 原先先取前六筆，然後直接渲染：

```js
const routeWorks = route?.construction?.nearby?.slice(0, 6) || [];
```

## 修復方式

顯示層先按相同工程編號及顯示資訊分組，再取前六組，合併項目顯示通報筆數；影響狀態、日期或內容不同的資料仍分開。此變更不刪除來源資料，也不改變施工幾何與通行驗證。

## 驗證

`node --test tests/construction-display.test.mjs` 的兩項通過，確認先分組再限制數量，以及不同影響或日期保持分開；`npm run build` 通過。桌面瀏覽器以台北小巨蛋至國父紀念館重測，寧安公園工程顯示一項並註記 10 筆通報，其他工程也能顯示。
